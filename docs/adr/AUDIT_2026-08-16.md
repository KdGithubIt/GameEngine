# ADR Audit — 2026-08-16

Status: Completed
Repository: `KdGithubIt/GameEngine`
Baseline: `a7b8ffcc333576e6c8860bee45c320350d65e5de`

## Scope

This audit separates two questions that had become mixed together after the ADR
sequence passed 100 records:

1. **Registry integrity:** Does every ADR exist, have a usable status, and appear
   in the chronological index with supersession represented correctly?
2. **Current-contract alignment:** Do the recent/cross-cutting ADRs, canonical
   specification, workspace structure, and representative implementation
   surfaces still describe the same architecture?

Registry integrity was checked across the complete `0001` through `0121`
sequence. Implementation alignment was intentionally risk-based rather than a
claim that every line of every historical ADR was re-proven against code.

## Registry result

The baseline contains 121 ADR files numbered continuously from `0001` through
`0121`.

- 117 records are Accepted.
- 4 records are Superseded.
- No live Proposed or Rejected ADR file was found in the numbered sequence.

The Superseded records are:

| ADR | Replaced by |
| --- | --- |
| 0019 | ADR 0022 |
| 0093 | ADR 0095 |
| 0108 | ADR 0112 |
| 0109 | ADR 0112 |

The previous `docs/adr/README.md` was not a faithful registry:

- it omitted ADRs 0093, 0094, 0095, 0102, and 0105;
- it placed 0019, 0108, and 0109 under a heading named `Accepted Decisions`;
- it contained a one-off ADR 0052 link above the index; and
- it retained a `Phase 41+ ADR Targets` table that duplicated a small historical
  slice after the repository had progressed to ADR 0121.

The reorganized index now distinguishes the current decision map from the full
chronological history and includes all five previously missing records.

## Current-contract alignment

### Runtime decomposition

ADR 0113's package set is present in the workspace: `core`, `assets`, `rig`,
`physics`, `animation`, `gameplay`, `render-runtime`, `platform`, `import`,
`scripting`, and `scene` exist alongside `renderer`, `engine`, `ecs`, and
`authoring`.

The audit does **not** interpret that as "every old `engine` file must be gone".
The `engine` package still contains compatibility facade modules and concrete
cross-domain composition, which ADR 0113 explicitly allows when moving the code
downward would introduce the wrong dependency direction or a cycle.

One real documentation drift was found inside ADR 0113 itself: its CI section
still described per-crate changed-path mapping and referred to full validation
on `master`. The current workflow derives package ownership from Cargo metadata,
forbids a duplicated package/path table, and uses `main`. The operational text
was updated without changing the runtime architecture decision.

### Canonical authoring specification

`docs/AI_FRIENDLY_AUTHORING_SPEC.md` had accumulated current-contract drift:

- Section 6 still presented the pre-0113 `graph`/`graph_bt` future workspace
  sketch instead of the current runtime-domain package structure.
- Section 7.2 still required compatibility loading for entities missing fields
  that ADR 0115 makes mandatory in the current format.
- Section 15 still described migration as part of the normal save pipeline even
  though ADR 0115 establishes current-format-only loading.
- Historical Phase 2.5 text referred to a nonexistent `Open Decision #7`.
- Section 23 still summarized ADR 0099 as retaining the legacy singular
  VMD/old-ID compatibility path that ADR 0115 removes.
- The single-version table still listed material schema version 2 even though
  ADR 0120 and the current authoring code use material schema version 3.
- The same table treated `project.json` as version 1 even though the current
  project identity contract is schema version 2 with `ProjectId` and
  `engine_version`.

Those contradictions were corrected. Historical phase descriptions remain in
the specification, but they are now explicitly subordinate to later Accepted
ADRs and current normative sections.

### Representative implementation checks

The following current surfaces were sampled because they exercise recent
cross-cutting decisions:

- ADR 0116: animation event installation is present through the animation
  runtime and scene-spawn integration rather than a separate component-level
  authoring event contract.
- ADR 0117: `ProjectId`, project schema version 2, and
  `engine-project-lifecycle` are present.
- ADRs 0118–0120: material schema version 3 and the generic
  metallic/roughness, occlusion, normal-scale, and occlusion-strength fields
  are present across authoring/runtime/import boundaries.
- ADR 0121: Editor MCP transport and shared Scene MCP/CLI authoring slices are
  present; the baseline includes the Scene CLI work merged immediately before
  this audit.

These checks support the conclusion that the recent architecture is broadly
tracking implementation. They do not certify every historical phase-specific
statement as current.

## What was deliberately not changed

- Historical ADR numbers and file names were not renumbered.
- Accepted ADRs were not marked Superseded merely because their implementation
  details are old; a later decision must actually replace the decision.
- Historical metadata formatting (`Status:` versus `- Status:` and title
  punctuation) was not normalized across 121 files, because that would create
  large review noise without changing the contract.
- No serialized schema, Stable ID, public Rust API, crate dependency, or runtime
  behavior changed in this audit.
- No `.github/**` or Dispatcher trust-boundary file changed.

## Follow-up

A lightweight ADR-registry checker would be useful to prevent future index
omissions and invalid status values. That should be implemented separately if
it is made a CI requirement, because CI/build infrastructure has a different
validation and trust-boundary impact from this documentation cleanup.

A second future cleanup may move long completed phase narratives out of the
canonical authoring specification into historical phase documentation. This
audit only corrected statements that could mislead a contributor about the
current contract.
